# Русский язык для DVinyl

Локаль интерфейса для [DVinyl](https://github.com/Kyonew/DVinyl), обновлённая под 4.0.0.

**English version:** [README.md](README.md)

**Состояние на 4 ноября 2026.** Апстрим русского ещё не поставляет: ни в `main`, ни в
`release/4.0.0` нет `locales/ru.json`, локаль и её регистрация лежат открытыми PR (#220 и #221).
Пока они не слиты, этот пакет — единственный способ получить русский интерфейс, включая 4.0.0,
у которой официального образа нет вовсе.

## Установка

**Из исходников — так сейчас выходит 4.0.0**

```bash
git clone https://github.com/Kyonew/DVinyl.git
cd DVinyl && npm install
/path/to/dvinyl-ru-locale/install-source.sh "$PWD"
npm start
```

Скрипт копирует локаль и накладывает девятнадцать правок регистрации; повторный запуск печатает
«уже применено» и ничего не меняет.

**Образ, собранный из ветки**

```bash
docker build -f Dockerfile.source -t dvinyl:ru .
```

`Dockerfile.source` клонирует ветку DVinyl из аргумента `DV_REF` (сейчас `release/4.0.0`) и
накладывает патч: официального образа 4.0.0 пока нет.

**Поверх официального образа**

```bash
docker build -t dvinyl:ru .
```

Этот файл кладёт локаль поверх `ghcr.io/kyonew/dvinyl:latest`, то есть подходит для уже
выпущенных версий. Другая версия — `--build-arg UPSTREAM=ghcr.io/kyonew/dvinyl:<тег>`.

**Готовый образ**

```yaml
services:
  app:
    image: ghcr.io/alexeyseo/dvinyl-ru-locale:2.0.0
```

Теги — на странице Packages репозитория; `latest` указывает на последний выпуск.

**Через агента**

Отдайте агенту этот репозиторий и задачу «поставь русский язык в DVinyl по AGENTS.md»: в файле
шаги, проверки и что делать, если апстрим изменился.

## После установки

Настройки → Язык → Русский.

`/login?lng=ru` отдаёт русскую страницу без входа — это самая быстрая проверка.

## Что правит патч

Семь точек регистрации, затем языковые правки, которые везёт пакет.

| Файл | Что делает |
|---|---|
| `locales/ru.json` | сама локаль, новый файл |
| `config/constants.ts` | `SUPPORTED_LANGUAGES`, `LANGUAGE_NAMES`, `DATE_LOCALES`, `decadeText`, `SUPPORTED_CURRENCIES` |
| `app.ts` | ресурсы i18next; `app.locals.decadeText` рядом с `dateLocaleFor` |
| `models/User.ts` | enum поля `language` — без него база не сохранит предпочтение |
| `views/settings.ejs` | выпадающий список в настройках: он держит свою копию списка языков |
| `views/setup.ejs` | подпись и список в мастере первичной настройки, тоже вписаны руками |
| `views/collection.ejs`, `core/views/detail.ejs` | деньги по языку интерфейса и запасная валюта |
| `views/partials/albums-filters.ejs`, `views/partials/active-filter-pills.ejs` | десятилетия по правилам языка |
| `plugins/music/partials/tracklist-view.ejs` | заголовок длительности через ключ локали |

`apply-ru-locale.js` делает каждую замену с проверкой «ровно одно вхождение». Если автор переписал
строку, сборка остановится с сообщением, в котором названа правка, — вместо интерфейса без языка.

## Когда русский появится в апстриме

**Патч кода перестаёт быть нашим.** Все девятнадцать правок регистрации становятся частью DVinyl,
и в этом репозитории остаётся один файл — `locales/ru.json`. С того релиза установка русского
сводится к обновлению образа.

Зачем пакет нужен после этого:

- **Старые версии, которые его уже не получат.** 3.3.0 и ниже останутся английскими навсегда —
  только этот пакет даёт им русский.
- **Обкатка перевода до релиза.** Правку формулировки можно собрать и потрогать здесь, пока релиза
  апстрима ещё нет.
- **И больше ничего.** Никаких копий файлов приложения и второго источника правды: правки
  формулировок уходят в апстрим пул-реквестом, а этот репозиторий только пересобирает локаль для
  старой ветки.

Как проверить, есть ли уже русский в релизе:

```bash
curl -sf -o /dev/null -w '%{http_code}\n' \
  https://raw.githubusercontent.com/Kyonew/DVinyl/<тег-или-ветка>/locales/ru.json
# 404 — русского нет, нужен этот пакет
# 200 — русский внутри, пакет не нужен
```

То же самое сообщает `watch-upstream.py`: строка «upstream has its own `locales/ru.json` now»
означает, что пакет можно снимать с сопровождения.

## Обновления DVinyl

- `locales/ru.json` — отдельный файл, обновления версии его не затрагивают.
- Точки регистрации опираются на строки в трёх файлах кода и четырёх шаблонах. После обновления
  пересоберите образ: строки на месте — правки применятся сами; автор их изменил — сборка
  остановится на «ожидалась ровно одна замена», и правку надо переложить.
- Строки, которых нет в переводе, показываются по-английски: i18next берёт `en.json` как запасной
  язык.

Локаль снята с `en.json` ветки `release/4.0.0`: 2376 позиций, расхождений нет, у плюральных строк
русские формы там, где в английском их две.

## Проверки

```bash
python3 scripts/check-locale.py          # паритет ключей и плейсхолдеры с апстримным en.json
python3 scripts/check-locale.py --ref main
python3 watch-upstream.py --always       # новые и пропавшие ключи, живость точек патча
python3 scripts/build-review-page.py     # одна HTML-страница: ключ, английский, русский, отметки
```

`watch-upstream.py` молчит, когда всё в порядке. CI гоняет обе проверки и русскую плюрализацию на
каждый pull request.

## Перевод

Правки формулировок, терминов и новых строк — через pull request. Порядок, стиль и словарь терминов
— в [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md). Если проще описать словами, откройте issue по шаблону
«Правка перевода».

Два правила, которые стоит знать до правки:

- **Термины правил карточных игр остаются в оригинале** (`Planeswalker`, `Tamer`, `Digi-Egg`,
  `Unit`, `Near Mint (NM)`), подписи полей — по-русски. У Digimon, Lorcana, Star Wars Unlimited,
  One Piece, Flesh and Blood и Yu-Gi-Oh! официальных русских карт нет, у Pokémon они были только
  в 2014–2016, а `Planeswalker` Wizards с 2008 года оставляют английским во всех языках.
- **Одна сущность — одно слово**: item → «запись», collection → «коллекция», location → «место»,
  copy → «экземпляр», release → «издание». Синоним в подписи — дефект, а не стиль.
