# Как помочь с переводом

Правки формулировок, терминов и новых строк — через pull request. Достаточно одного файла:
`locales/ru.json`.

**English version:** [CONTRIBUTING.md](CONTRIBUTING.md)

## Что сделать

1. Форкнуть репозиторий и создать ветку.
2. Поправить нужные значения в `locales/ru.json`. Ключи не менять, плейсхолдеры `{{…}}`
   сохранять дословно.
3. Прогнать проверки — без них pull request не пройдёт:
   ```bash
   python3 scripts/check-locale.py
   node .github/scripts/pluralization-check.js
   ```
4. Открыть pull request: что было, что стало и почему. Если правите несколько мест — списком.

## Стиль

Информационный: глагол первым, без «пожалуйста» и «ваше», без канцелярита. Опасное действие говорит,
что именно пропадёт: «Удалить список «{{name}}»? Записи из него останутся в коллекции».

## Термины

Держим единообразие, иначе в интерфейсе будут «пластинки» и «записи» вперемешку.

- item → запись
- release → издание
- pressing → прессинг
- wishlist → желаемое
- shelf → полка
- track / tracklist → трек / треклист
- cover → обложка
- barcode → штрихкод
- rating → оценка
- publisher → издатель
- location → место

Названия сервисов не переводим: Discogs, TMDB, IGDB, ScreenScraper, Rebrickable, BoardGameGeek,
GoodReads, Libib, Hardcover, Open Library, Musik-Sammler.

## Множественное число

В английском две формы, в русском три: `_one`, `_few`, `_many`. Если правите такую строку, правьте все
три. Пример: `{{count}} трек` / `{{count}} трека` / `{{count}} треков`.

## Новые строки апстрима

Если в DVinyl появились новые надписи, они показываются по-английски — i18next берёт `en.json` как
запасной язык. Закрыть их можно тем же способом: дописать ключи в `locales/ru.json`.
